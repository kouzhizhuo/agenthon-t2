## Executive summary (read this first)

The third candidate adds bounded, cited economic scenarios to an already complete numerical forecast. It uses only the organizer-injected House route in restricted mode. Every scenario has a joint weight, one path-wide uncertainty multiplier, and a bounded shift measured in the numerical forecast's own standard deviation for each requested cell. A no-additional-effect continuation is required. Invalid output, absent network credentials, stale documents or transport failure retains exact numerical samples and reports the actual reason. Local tests verify the interface and arithmetic, not House identity or predictive benefit.

For example, a two-horizon rate forecast can retain a continuation scenario and add a cited higher-uncertainty scenario. One scenario is sampled for each complete original joint draw; the same label applies to both horizons and every asset. No cell is independently shuffled. The underlying numerical samples retain their dependence inside each scenario. Arbitrary cell shifts can still change horizon increments and pairwise variograms, so neither dependence accuracy nor calibration is guaranteed.

## Inputs and permitted route

`source/house_scenarios.py` exposes `apply_scenarios(samples, evidence, docs, card, asof, request_fn=None)`. It supports the frozen F1, F2 and F4 study. F3 retains its numerical baseline pending a separately designed cross-asset study. There is no task-ID-specific rule or dated event lookup.

Production requires `QFBENCH_NETWORK=restricted`, `MODEL_ENDPOINT`, `MODEL_TOKEN`, `MODEL_NAME` and the authenticated `http_proxy` receipt. The model endpoint must be an origin with no extra path, user credentials, query or fragment. The production transport matches the current official reasoning example: an explicit standard-library `HTTPConnection` connects only to the HTTP receipt proxy and sends the absolute `http://model-origin/v1/chat/completions` URI. It supplies the bearer token and model alias, plus `Proxy-Authorization: Basic` using the URL-decoded injected proxy credentials. No direct target connection or fallback is available. `NO_PROXY`, even `*`, cannot bypass the receipt connection. An invalid, missing or unauthenticated proxy refuses the attempt. The module does not edit or clear proxy variables, call vendor models, follow redirects or fetch new data.

One request asks for at most 4,000 output tokens with temperature zero, one completion and no tools. Thinking is disabled through the approved top-level `chat_template_kwargs` option. Timeout is 90 seconds. A transient HTTP 429/500/502/503/504, connection error or timeout can retry once, with no separate wait; the physical request ceiling is two. An HTTP 401/403 is refused without retry. Malformed completed output is not repaired through further requests. Physical requests are counted in the receipt. Admitted request counts are unknown because admission is organizer-side.

## Evidence and prompt

Only nonempty documents published on or before the as-of and within 90 days are eligible. Duplicate document identifiers refuse the attempt. Most recent documents are selected first, at most eight, with at most 10,000 characters per document and 45,000 total characters. Large scraped pages are reduced to literal economic paragraphs in original order. The keywords cover positive and negative terms equally, including growth, inflation, employment, crisis, recession, risk and uncertainty. Navigation paragraphs without economic content are omitted. The report discloses excerpt length and limits; omitted text may still contain contrary evidence.

The system prompt treats the corpus as untrusted data, prohibits instruction changes, external tools and historical-memory outcomes, and asks for competing economic mechanisms. It supplies numerical center, spread, target type, unit, exact requested grid and monthly panel steps. It asks the model to consider contrary evidence and avoid double-counting information already reflected in the panel. Scenario names cannot carry digits, so a future point or dated outcome cannot be hidden in that field. Exact schema validation refuses additional keys such as an absolute future price or target value.

Quotation verification establishes that a passage is present in a sent, cutoff-safe document. It does not establish causal relevance, scenario probability or predictive skill. Text injection can still influence a language model's judgment; the strict schema and bounds prevent it from granting tools, changing the route or importing a target value into an absolute-point field. They do not prove economic understanding.

## Output schema and transformation

The sole JSON object must contain two or three scenarios. Each must supply a unique descriptive name, positive weight, width in `[1,1.5]`, and every requested asset/horizon cell exactly once. Weights sum to one. `delta_sigma` must be strictly between -0.5 and +0.5; booleans, nonfinite values, duplicate JSON keys, wrong asset IDs and wrong horizon types are refused. Every nonzero shift or width above one requires literal citations for all affected cells. A continuation scenario must have width one and all shifts zero. Citations are at most four per cell and literal contiguous passages of 20–1,200 characters from the sent excerpts.

For original joint draw `X`, numerical cell mean `m`, standard deviation `s`, selected scenario width `w`, and scenario cell shift `d`, the output is `m + w*(X-m) + d*s`. The width applies to the entire path. Seeded scenario labels are independent of draw values and reproducible for a fixed response. The module refuses nonfinite results and nonpositive FX log-level outputs. It also rejects a sampled mixture that narrows any empirical marginal spread, despite permitted widths being at least one. This is a mechanical protection, not a guarantee against poor quantiles or scores.

Successful application sets the main method to `v3-cited-house-scenarios`. Fallback keeps the numerical method and original sample object. Both record the attempted strategy, retained method, physical calls, timing and reason. The report always says `actual_House_inference_verified=false`. It separately records whether the real HTTP client received a response from the configured endpoint and the response's model field. Serving identity and deployment provenance remain unverified by the client. Loopback tests are explicitly controlled transport, never actual House evidence.
