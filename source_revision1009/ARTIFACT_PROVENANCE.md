## Executive summary (read this first)

This revision contains permitted numerical forecasting algorithms and a separately deployed optional House scenario candidate. It carries no packaged learned model, external model weights, target bank, practice answer, or fitted per-card parameter table. Every numerical fitted statistic comes from the current task's supplied observations at or before its as-of. Dated text facts are verified during the same execution. The House candidate uses the organizer's remotely served model; it does not package that model.

For example, a release published before the cutoff may state a new seasonally adjusted observation absent from the lagged panel. Its text, publication date and exact quotation travel into the local rationale. A release after the cutoff cannot contribute. A non-seasonally-adjusted CPI level cannot replace the seasonally adjusted series.

V2 is the frozen retained comparison. Its three runtime source files and immutable published image are recorded in the source freeze. The startup as-of resolver is retained from the already verified repair. The release and stationary-block modules were authored on 9 October 2026 from the task specifications and generic statistical algorithms. They contain no trained or calibrated coefficients. Pool weights, reservoirs and block lengths are declared in PROTOCOL.md before candidate scores.

The 346 historical cases, seeds, local normalization and the 95-unit subset have been reused in previous research. Candidate selection on those results is development selection. It is not a prospective holdout, independent replications, or organizer reference-scale agreement. No source package or image includes those observations or realized targets. Official held-out performance remains unknown until the organizer evaluates an uploaded image.

The numerical image built from Dockerfile selects the release strategy by default and does not invoke the House path during the official forecast command. Its descriptor uses category api with models []. The source also contains House support so that Dockerfile.house can deploy a separate image with T2_STRATEGY=house. Merely bundling that module does not establish a model call or contribution in the numerical image.

The House candidate was appended after the initial numerical roster as a structural and interface candidate. It is not part of the numerical roster fixed before those scores, and its local offline tests establish fallback, schema, transport and arithmetic behavior only. A real organizer evaluation is needed to establish prediction quality. Its descriptor must use the published model row: name nvidia/nemotron-3-super-120b-a12b, version rl-030326-fp8, revision rl-030326-fp8, training_cutoff unpublished, access api. This disclosure remains required when an offline smoke test follows the numerical fallback. Actual production calls use only the injected endpoint, bearer token, model alias and authenticated receipt proxy. The organizer permits at most 25 admitted calls per unit, each with at most 4,000 output tokens; this module makes at most two physical attempts. No outside model endpoint is permitted.

Only public organizer repositories and the owner's public kouzhizhuo/agenthon-t2 repository are used. All generated local artifacts stay under T2. No archived personal material, removed access skill, company compute or personal remote compute is used.
